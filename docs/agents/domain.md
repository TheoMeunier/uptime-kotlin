# Domain documentation

This repository uses a single domain context.

Before exploring, planning, reviewing, or changing the application:

1. Read `CONTEXT.md` at the repository root.
2. Read relevant architectural decisions under `docs/adr/` when the directory exists.
3. Use the vocabulary defined in `CONTEXT.md` in code, tests, issues, and documentation.
4. Surface any conflict with an existing ADR explicitly instead of silently overriding it.

If a durable domain concept is introduced or renamed, update `CONTEXT.md`. If a durable architectural trade-off is decided, add an ADR under `docs/adr/`.
